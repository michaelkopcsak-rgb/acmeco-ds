# Notes and glossary

Terms as they come up, in plain language. Newest at the bottom of each section.

## Design system terms

- **Design token:** a named design decision (`color.text.default = #1c1c1c`) stored as data, so code and Figma use the same value and a change happens in one place.
- **DTCG:** the W3C Design Tokens Community Group format: JSON where each token has `$value`, `$type` and `$description`.
- **Primitive / semantic / component tokens:** the three tiers. Primitives are raw values (`brand.700`). Semantic tokens give them a meaning (`color.action.background.default`). Component tokens say where one component uses them (`button.primary.background.default`). Components only use the last two.
- **Evidence label:** OBSERVED, LEGACY-NAMED, PROPOSED, BENCHMARK-INFORMED or REFERENCE-OBSERVED, recorded on every token and decision (see `CLAUDE.md`).
- **Rationalise:** replace several drifting values with one system value (for example 2, 3 and 4px radii → 4px).
- **Contrast ratio:** how distinguishable two colours are, from 1:1 (identical) to 21:1 (black on white). WCAG AA needs 4.5:1 for body text and 3:1 for large text and control boundaries.
- **Headless primitives:** components that supply behaviour (keyboard, focus, screen-reader semantics) but no visuals. React Aria Components is one; we style it with our tokens.
- **Contrast pair:** a foreground token and the background it's designed to sit on (`color.text.link.default` on `color.surface.subtle`), with the minimum ratio it must reach. Listed in `tokens/contrast-pairs.json`.
- **Compositing:** working out the actual colour a translucent token produces on what's behind it. The contrast check does this, e.g. 85% white over a black photo becomes `#d9d9d9`.
- **Scale token vs component token:** spacing, radius and border width exist only as primitive scales (`space.4`). A component never uses them directly; its component token points at them (`button.padding-x → {space.4}`), so changing one component's spacing never moves another's.
- **Stand-in font:** a freely licensed typeface used in place of a proprietary one. Here Outfit stands in for the legacy brand typeface, which we hold no licence for.
- **Card:** AcmeCo's own class name for a listing card in search results. Cards come in three tiers (tier 1 largest, tier 3 a compact row) that the advertiser pays for; our `tier` prop mirrors them.
- **Stretched link:** one real link (the card's title) whose invisible `::after` covers the whole card, so the card is clickable while screen readers hear a single link, not a card full of them. Buttons on the card sit above it.
- **Fixture:** made-up but realistic data (listings, brokers) used by stories and tests. Ours is synthetic: no real listings, people or logos; photos are drawn illustrations labelled as placeholders.
- **Description list (`dl`):** the HTML list for label / value pairs: each `dt` (the label) is followed by its `dd` (the value), and screen readers read them as pairs. FactList is one.
- **Container query:** CSS that responds to the width of the box a component sits in rather than the window (`@container (min-width: 560px)`), so a FactList shows two facts a row in a wide column and one in a narrow card on the same page.
- **Prototype (in this repo):** the real coded screens wired together so they can be clicked through (`src/prototypes/`), compiled into a standalone page. Unlike a Figma prototype, every state is the working component: filters filter, dialogs trap focus, screen readers hear the real names.

## Tooling terms

- **Repository (repo):** the project folder plus its full change history, tracked by git.
- **Commit:** one saved, described change in the history.
- **Branch:** a separate line of work, so changes can be reviewed before they reach `main`.
- **Pull request (PR):** a request to merge a branch into `main`, where checks run and changes are reviewed.
- **Private repo:** visible only to people you invite.
- **Scaffold:** the starting set of config files a project needs before any real code exists.
- **`package.json` / `node_modules` / `package-lock.json`:** the project's list of tools and libraries, the downloaded copies, and the exact versions installed (so every machine gets the same ones).
- **Install script:** code a library runs while it's being installed. npm now asks before running them, which is why it flagged `esbuild`.
- **Style Dictionary:** the tool that turns token JSON into CSS variables.
- **Storybook:** a workshop app that shows every component and state in isolation, with docs and accessibility checks.
- **Chromatic:** a service that screenshots every Storybook story and shows what changed visually in each PR.
- **CI (continuous integration):** GitHub Actions running the checks (lint, type check, token drift, Storybook build, Chromatic) on every PR.
- **GitHub secret:** a value (like the Chromatic token) stored encrypted in GitHub, usable by CI but never shown or written into files.
- **Changeset:** a small file in a PR that records whether the change is a patch, minor or major version bump, and why.
- **CODEOWNERS:** a file listing who must review changes to which paths.
- **Self-test:** a check that runs against deliberately bad and good sample files first, to prove its rules still catch what they should. `npm run check:tokens` does this before checking the real files.
- **Type stripping:** Node can run TypeScript files directly by ignoring the type annotations, so the contrast script can share `src/lib/contrast.ts` with Storybook.
- **Exit code:** the number a command reports when it finishes. 0 means success; anything else makes the CI step fail.
- **Figma variable:** Figma's version of a design token. Grouped into **collections** (here Primitives and Semantic), each with **modes** (Value; Light). A semantic variable can be an **alias** that points at a primitive, just like `{color.gray.900}` in the JSON.
- **Scope (Figma):** which property pickers a variable appears in. Primitives have none, so designers can't pick them by accident.
- **Code syntax (Figma):** the code name Dev Mode shows for a variable, here the CSS variable, e.g. `var(--color-text-default)`.
- **Digest / fingerprint:** a short code computed from a lot of data. If two digests match, the data matches. Used to prove Figma equals the repo after a sync.
- **Interaction test / play function:** code attached to a story that clicks, types and checks the result (e.g. "pressing Enter calls onPress"). `npm test` runs every story this way in a real browser, with accessibility checks, and CI fails on any failure.
- **Pending (loading) state:** React Aria's name for "busy": presses are ignored, focus stays, and screen readers are told. Different from disabled, which removes focus.
- **Guidance file:** `<Component>.guidance.md`, the written usage rules for a component. Shown on its Storybook docs page now, and on its Figma page in phase 5.
- **Icon registry:** `src/icons/index.ts`, the one list of icons the system uses. Components import icons only from it (the token check enforces this), and phase 5 builds the Figma Icons page from it.
- **Type-level test:** a file of code that must *not* compile, each line marked `@ts-expect-error`. If a rule loosens (e.g. IconButton's `label` becomes optional), the marker goes unused and the type check fails. See `IconButton.typetest.tsx`.
- **Toggle button / aria-pressed:** a button that switches on and off (save). Screen readers announce "pressed" or "not pressed".
- **Field tokens:** `tokens/components/field.json`, shared by every form control (label, hint, error, border, sizes), so form controls can't drift apart.
- **Stacked branch:** a branch started from another unmerged branch (TextField from Link). Once the first PR merges, merge `main` into the second and its PR shows only its own commits.
- **Popover / portal:** a layer (like Select's list) attached to the page body, outside the component, so it isn't clipped. Tests look for it across the whole page (`within(document.body)`).
- **Accessible name:** what a screen reader announces for a control. Tests check it with `toHaveAccessibleName`.
- **Token drift check:** CI rebuilds `tokens.css` from the JSON and fails if it differs from the committed file, which catches hand edits to generated output.
- **Modal / backdrop:** a modal dialog blocks the page until it's closed; the backdrop is the dimmed layer behind it (AcmeCo's: black at 60%). "Dismissable" means a click on the backdrop closes it.
- **Focus trap:** while a dialog is open, Tab moves only between the controls inside it; when it closes, focus goes back to the button that opened it. React Aria's Modal does both.
- **Scrollable region:** an area with its own scroll bar. If it holds only text, a keyboard user can't reach it to scroll unless it can take focus; axe's `scrollable-region-focusable` rule checks this.
- **Live region / log:** an area whose changes screen readers announce without moving focus. `role="log"` suits a conversation (new messages are read as they arrive); `role="status"` suits a one-off message ("Connecting to AcmeCo AI").
- **Toggle button:** a button that stays on or off (Voice Mode); screen readers hear "pressed" or "not pressed". A button whose label changes instead ("Mute microphone" / "Unmute microphone") is the other accessible pattern.
- **Layer boundary / boundary check:** the rule that AcmeCo components are built only from the system (foundation components, tokens, icons, hooks, data types), never from packages or sample data directly. `npm run check:boundaries` enforces it in CI; the few exceptions are listed with reasons in `scripts/boundary-exceptions.json`.
- **Container query:** CSS that reacts to the width of a component's container rather than the whole window (`@container (max-width: 400px)`), so a card header stacks when the card is narrow, wherever it's placed. The token check allows px in the condition, as it does for `@media`, because CSS variables can't be used there.
- **Parity check:** comparing the Figma components with the rendered code, field by field. `scripts/figma/parity-code.mjs` reads the code side from Storybook with Playwright (a script-driven browser); `scripts/figma/figma-parity.js` reads the same fields in Figma and lists every difference.
- **Box model / border-box:** how a box's size adds up: content + padding + border. In CSS (with `box-sizing: border-box`) the border sits inside the box and pushes the content in; Figma does the same when an outline takes layout space (`strokesIncludedInLayout`, on by default for new frames).
- **Inset (start / end):** the distance from a component's edge to a part inside it (the text, the Search button). It checks border + padding together, which separate padding numbers can't.

## Lessons (this repo)

- **MDX isn't quite Markdown.** Storybook's `.mdx` pages don't support Markdown tables without the `remark-gfm` plugin, so tables there are written as HTML. And `*` inside HTML in MDX can be read as italics: write `<code>{'--legacy-*'}</code>`, not `<code>--legacy-*</code>`.
- **Secrets in CI stay in one step.** The Chromatic token is visible only to the step that checks for it and the Chromatic step, never to `npm ci`, where third-party install scripts run.
- **Chromatic needs at least one story.** A docs-only Storybook (just the Welcome page) fails with "Cannot run a build with no stories". The first story is the Outfit typeface specimen.
- **Round contrast down, never up.** The check rounds down, so a ratio of 4.496 can never be shown as a passing 4.50.
- **Test that a check can fail.** The contrast check was run once with AcmeCo's original control border (`#b1b3b0`) to confirm it fails (2.11:1, exit code 1) before trusting its passes.
- **Deleting a story file can break the running Storybook.** Its story index still points at the old file ("Unable to index … ENOENT"). Restart Storybook; the code is fine.
- **Disabled samples must be real disabled controls.** WCAG exempts disabled controls from contrast, not text that merely looks disabled. The accessibility scan correctly flagged the Contrast page's disabled "Aa" samples until they became `<button disabled>`.
- **Figma stores descriptions as HTML.** An apostrophe goes in as `'` and comes back as `&#39;`. Compare decoded text, or every sync looks "changed".
- **Don't trust an import tool on your files without a dry run.** The token import skill would have turned every colour into text (it ignores group-level `$type`) and couldn't link Semantic to Primitives. Running its parser read-only first found both.
- **A fingerprint finds problems you didn't think to check.** The first Figma digest mismatch led straight to the HTML-description quirk.
- **React Aria states are data attributes, not CSS pseudo-classes.** `data-hovered`, `data-pressed`, `data-focus-visible`. The pseudo-states addon can't force them, and React Aria strips them if passed as props. `src/storybook/ForceState.tsx` sets them on the element after render instead.
- **zsh stops a whole command on a pattern that matches nothing.** `rm -rf a b/*/c` deleted nothing because `b/*/c` matched nothing. Check the result rather than assume.
- **Adding a package while an old Vite cache exists can fail the first test run** ("Failed to fetch dynamically imported module"). Run it again; a cold run (as in CI) passes.
- **Strict prop unions and Storybook args don't mix well.** IconButton forbids e.g. `onPress` on a toggle; spreading Storybook's generic `args` breaks that. Stories that render the component themselves pass explicit props.
- **A double focus ring (white inside, ink outside) always shows:** on a dark photo you see the white ring, on a light one the ink ring. AcmeCo already uses one; it was in the audit's shadow data.
- **Never let a test click a real link.** It navigates the page running the test and crashes the runner ("Browser connection was closed"). Wrap the story in React Aria's `RouterProvider` with a stand-in `navigate` function: no navigation, and it proves Link works with client-side routing.
- **A failing contrast pair can be the wrong requirement.** Link blue vs ink body text is 2.50:1, but the 3:1 rule only applies to links marked by colour alone; inline links are underlined. The pair was removed and the finding recorded in the token and the guidance, rather than "fixed" by changing a colour.
- **React Aria's SearchField gives every button inside it the "clear" behaviour.** A submit button inside needs `<ButtonContext.Provider value={null}>` or it clears the field instead of submitting. A test checks this.
- **A hidden element is gone, not just invisible, to tests and screen readers.** `queryByRole` returns nothing for `display: none`; assert `toBeNull()`, not `not.toBeVisible()`.
- **Stories whose tests click are photographed mid-hover by Chromatic** (the pointer stays put), e.g. Link "Inline" shows its 2px hover underline. Kept as is by choice (2026-10-09); the States matrix stories show the resting look.
- **Check a nested button's fit by measuring the inset on every side,** border included. The hero submit was 4px top and bottom but 5px on the right until the border width was subtracted.
- **Check the accessible name, not just the visuals.** A compact Select showed "Property type" as its text and was also labelled "Property type", so screen readers heard it twice. Before a choice, the repeated text is now hidden from screen readers; React Aria then reads value + label ("Newest, Sort").
- **A test that passes "most of the time" has a bug; run it many times to find it.** Select's Default test failed about 1 run in 4 because it checked that focus had returned to the trigger instantly, while React Aria returns it a moment after the list closes. Fixed with `waitFor(...)`; 12 then 6 clean runs. (When PR #10 was built I put two failures down to a stale cache after edits. One was probably this race; the other, a "syntax error" in code that compiles, did look like a cache problem.)
- **In Storybook, a story's decorators add to the shared (meta) decorators; they don't replace them.** To give most stories a wrapper but not the States matrix, put the wrapper in the shared `render`, which a story's own `render` does replace.
- **React Aria often adds context to a button's name.** A Tag's remove button is named "its label + the chip's text", so `aria-label="Remove"` is announced "Remove Colorado"; writing "Remove Colorado" gave "Remove Colorado Colorado". Same family of problem as the compact Select. Check names with `toHaveAccessibleName` / `getByRole(..., { name })`.
- **Some React Aria components render their items in a second pass** (collections like TagGroup), after a parent's layout effect. `ForceState` now uses a MutationObserver to re-apply forced states when elements appear.
- **A target inside a bordered element loses the border width.** The chip's remove button was 22px inside its 1px borders; it now reaches over them to a full 24px.
- **Model data once, format it once.** Listing data lives in `src/data/` (types, fixtures, formatters such as `priceText`), so every part shows "$28.50 /SF/YR" the same way and speaks it as "per square foot per year". The prototype formatted prices in several places.
- **Clipping never hides an element's own outline.** `overflow: hidden` on the card clips its children (the photo follows the rounded corners), but the card's own focus ring still draws outside it. Turning clipping off while focused was unnecessary and let the photo's square corner poke out.
- **To test a stretched link, click what's actually on top.** `userEvent.click(element)` sends the click to the element you name, not to whatever covers it, so the card test finds the topmost element at a point with `elementFromPoint` (the title link's invisible cover) and clicks that.
- **A fade-in can fail a visibility check.** jest-dom's `toBeVisible()` counts opacity 0 as invisible, so a check made in the first frames of a dialog's fade failed about half the time. Wait for the fade (`waitFor(... toBeVisible())`), then assert what matters (the dialog is still open, not "visible").
- **Check the captures before re-using an old sketch.** The foundations proposal sketched Dialog at 16px with a deeper shadow; the captured CSS showed AcmeCo's newest dialog at 8px with our existing raised shadow, and a sign-in modal that runs off phone screens (decision 28).
- **A script that rewrites a whole JSON file reformats it.** Adding one shadow to `primitives.json` with `json.dump` turned a 4-line change into a 396-line diff, because the file is hand-formatted. Insert new tokens as text in hand-formatted files; `json.dump` is fine only for files that were written by it.
- **A check finds what review missed.** The first run of the boundary check found PropertyCard reading brokers from the sample data, which every review had passed over: it worked in Storybook but could never show real data.
- **A loading button that disappears leaves an announcement pointing at nothing.** React Aria announces a button's label when its loading starts and ends, by referring to the button, and keeps the announcement in the page for 7 seconds. Swap the label on one button ("Contact Broker" → "Done") rather than replacing it; in tests, `clearAnnouncer` from `react-aria/private/live-announcer/LiveAnnouncer` clears leftovers once the dialog has closed.
- **A button outside a form can still submit it:** `form.requestSubmit()` runs the form's own submit handling (and validation), which is how the dialog's sticky footer sends the contact form.
- **When one test fails partway, later stories in the same run can fail for its leftovers** (an open dialog, a live announcement). Fix the first failure before reading the others.
- **Fix the gap, keep what works.** AcmeCo's sign-in buttons lacked only names; replacing them with full-width dark blue text buttons changed layout, colour and emphasis for no reason, and the owner rejected it in review. The fix kept AcmeCo's round buttons and added names.
- **Check a brand asset's licence before using it, not just its source.** Official sign-in artwork from Google, LinkedIn and Apple is licensed for sites that actually offer that sign-in; Apple's also needs a developer membership and a click-through agreement. A prototype uses neutral placeholders instead.
- **Decorative text inside a named button can trip axe's label-in-name rule** ("in" on a button named "Continue with LinkedIn"). Draw purely decorative marks with CSS (`content: attr(data-mark)`).
- **Scope by rule, then read the result.** Figma variable scopes (which pickers a variable shows in) for 410 component variables come from rules on each token's name, and a token no rule covers stops the build. The first rules still misfiled a handful ("divider.text" as a line colour, "name-font-size-lg" as a size, the spinner's stroke as a box size); listing every variable by scope and reading it caught them before Figma did.
- **A digest can check work done in pieces.** Each chunk of the Component collection reports the digest of the whole collection; it equals the repo's only once every chunk has run, so a skipped or stale chunk can't go unnoticed.
- **Check parity against the rendered code, not the spec that generated the design.** The Figma Button was built from a spec; comparing it with that same spec would always pass. The parity check instead reads the computed styles of the real buttons in Storybook's States matrix (`figma/parity/button-code.json`): 648 of 648 values matched.
- **Figma draws a shadow's spread only on frames that clip their content, and no shadow at all on a frame without a fill.** A focus ring drawn as a shadow vanished on the transparent tertiary button; it's now a separate outline layer ("Focus ring"), as the code's outline is.
- **Send the generator, not its output.** Button's 54 expanded variants were 40,000 characters, too big for a Figma script; its spec file (the code that makes them) is a few thousand, so Figma runs the spec and builds all 54 in one call.
- **Check geometry, not just values.** The Button pilot passed 648 of 648 checks, yet primary and tertiary buttons were 2px narrower than the code: the CSS gives every button a 1px border (transparent unless shown), and Figma counts an outline in the layout only if it exists. Width wasn't among the checked fields. Parity now checks widths and text insets, and the specs mirror the CSS box model: a transparent outline (a 0% paint; a hidden one takes no space), an inset layer for the invalid fields' second pixel (the CSS's inset shadow), and calc paddings set as numbers (the hero's field/gap minus the border).
- **An icon's line weight scales with it in code, not in Figma.** Lucide strokes are in its 24px drawing's units, so a 16px icon draws 1.33px lines; Figma scales an instance's shapes but keeps the stroke at 2px. The generator now sets each icon's stroke to `weight × size / 24`.
- **Figma rounds a text box's width up to a whole pixel,** so a component that hugs its text can be up to 1px wider than the browser's fractional width (Button sm: 121 vs 120.28). Parity allows widths 1px and also reports the strict count.
- **Pressing is hovering too.** The States matrix's forced Pressed state also sets hovered, as a real mouse press does, so an unchecked checkbox's border darkens when pressed. The first spec missed it; the parity check caught it.
- **A table cell's width is a request, not a rule.** The States matrices give field cells 280 or 320px, but the table shrinks them, so the rendered fields are narrower. Field widths aren't compared; Figma shows fields at a representative width.
- **A spinning element's box grows as it turns.** `getBoundingClientRect` on a rotating spinner gave 22.43px for a 20px spinner; untransformed sizes (`offsetWidth`) are used for anything with a transform.
- **Every JavaScript string has a `.sub()` method** (an old HTML helper), so `if (x.sub)` is true for any string. Test the type (`typeof x === 'object'`), not for a property.
- **Dry-run a spec against the code before building it.** Resolving each spec's variables in Node and comparing them with the measured code values caught the field-width mismatch before any Figma call; only the box-model differences needed Figma to show.
- **A Figma text property is one text for the whole set.** Linking every badge's label to a "Label" property set all four to "Office", Auction included, and editing one variant changed them all. Text properties are now only for layers that say the same thing in every variant (the generator refuses others); Badge has none, and its text is edited in an instance.
- **Compose in Figma as the code composes.** The Dialog's Close and footer button are instances of the Icon button and Button sets, not redrawn copies, so a change to Button reaches every dialog, and parity checks them through the dialog (52/52).
- **Not every component is a States matrix.** Parity can now read the component itself (`cells`) across several stories: Badge's "All tones", the Chip rows, and the dialog, which opens outside the story's canvas (a portal), one size per story.

- **Upload images as bytes, not as script text.** The placeholder photos were too big to send as base64 inside a Figma script. `scripts/figma/build-images.mjs` renders them to PNG, and the Figma MCP's upload_assets puts the raw bytes into a placeholder rectangle. Figma's image hash is the SHA-1 of the bytes, so `figma/images/manifest.json` proves the right image landed.
- **`findOne` can miss layers inside nested instances.** In the card variants, `findOne` returned nothing for a layer inside a part instance that `findAll` found. The Figma-side scripts use `findAll(...)[0]`.
- **Measure the narrow layout before drawing it.** On a 343px card the broker row wraps: the logo takes its own line and the brokers wrap below at full width. Reading the code's positions (0,0 / 147,0 / 0,64) gave the "Row narrow" variant, which now matches exactly. A plain wrapping row put the brokers beside the logo and overflowed.
- **Compare whole heights for composed components.** Each part can match while the card as a whole drifts (a missing gap, a wrapped line). Parity checks each card's height too, and all six equal the code's.
- **Docs read the guidance file as written,** so the generator turns a markdown table (PropertyCard's tier table) into "a: b" lines, and a part with no colour pairs of its own (Property media) says so instead of showing an empty list.
- **Measure insets from the component, not the first part listed.** The first card run measured the title's inset from the header's own box. Parity now measures from the root part (the one with no layer).
- **A test that clicks leaves its mark on the capture.** The Contact module and Contact form stories run tests that press Message and Send, which then stay hovered, so the code side read the hover dark blue. Those buttons are compared by size only; their colours are checked on the Button page, where nothing is clicked.
- **An empty Figma frame keeps a 100px default.** The Assistant's spacer (a CSS `flex: 1` with nothing in it) made every panel 68px too tall until it was given a 1px height. Compare whole heights: that's what caught it.
- **Figma can bind a gradient's colours.** Each stop of a gradient paint takes a variable (`boundVariables.color`), so the Assistant's navy-to-blue edge stays tied to its tokens; the lint now counts gradient stops too.
- **A layer links to one effect style.** The assistant panel's raised shadow and glow are two styles in the system, so the layer copies both styles' effects; changing either style won't update it until the page is regenerated.
- **Selectors by position break when hidden elements move.** `form > div:nth-child(4)` missed the Select because React Aria adds hidden elements; parity selectors now use class names.
- **Count where you measure from.** The connecting bar's and launcher's insets are measured from their outer edge, border included (2px gradient edge + 16px padding = 18px); Figma counts the stroke in the layout the same way.
- **Copying data by hand into Figma is where errors creep in.** The full parity data is about 80,000 characters, and Figma scripts can't read files. So the report cites each set's latest recorded run, after `git log` confirmed that nothing in `src/` or `tokens/` changed during phase 5. A fresh read-back of every set's variant count confirmed the Figma side. The bundled re-run scripts (`render-components.mjs report`) are there for when the code changes.
- **A lint that ignores gradients reports false failures.** The white "Voice Mode" label read as 1:1 because the lint skipped the gradient and measured against the white panel behind it. It now measures against every gradient colour and keeps the lowest (6.8:1 here).
- **Say "disabled" where the lint can see it.** WCAG exempts disabled text, but the lint only knew whole variants named "Disabled". A disabled option inside a list is now marked in its layer name ("Option 4 label (disabled)").
- **Generate the Cover too.** The status line was written by the phase 2 sync and would have reverted to "in progress" on the next run. The Cover is now written from the repo (`render-components.mjs cover`), like every other page.
- **Tabs vs TabSelector** (glossary): Tabs switch between panels of content in place, and say "tab" to a screen reader. TabSelector looks like tabs but sets a value (For Sale / For Lease), so it is a radio group. Pick by what the control does, not by how it looks.
- **Restart Storybook after switching to a branch without some story files.** Its story index still listed the Layout stories from the previous branch, so every page failed with "Failed to resolve import".
- **Wait for React Aria collections in tests.** Tabs (like other React Aria collections) render the list first and the items a moment later. Chromatic's faster browser ran the test in between ("Unable to find … role tab"), while local runs and CI passed. Use `findBy…` (which waits) for collection items, not `getBy…`. Breadcrumbs (also a collection) hit the same failure in PR #61: check every React Aria collection component (Tabs, Breadcrumbs, TagGroup, Select, Menu, Table) for it before pushing.
- **Popover vs Dialog** (glossary): a Popover is a panel attached to the button that opened it (a menu, a filter), and the page stays in view around it. A Dialog is a task with its own title and actions, centred over the page. Both move focus in and return it on close.
- **Disclosure** (glossary): a button that shows or hides the content after it, and says whether it's open. A row of disclosures with headings is an accordion.
- **…and wait for their state, not only their items.** The next Chromatic run found the tabs but read the first one as not selected yet: React Aria sets the selection a moment later still. Interaction tests now wrap state checks in `waitFor` (selected, expanded, focus). Local runs and CI never showed either gap.
- **React Aria stops pointer events from bubbling.** Its press handling calls stopPropagation, so a parent's `onPointerDown` never fired and the language dialog couldn't tell a click from a key press. Listen in the capture phase (`onPointerDownCapture`) when a wrapper needs to know.
- **Don't close on every change of a radio group.** Arrow keys change the choice as they move, so "apply and close" on change would shut the dialog on the first arrow press (WCAG 3.2.2, On Input). Pointer choices close it; with the keyboard, Enter does.
- **Follow a reference screenshot for interaction states.** Menu rows on AcmeCo get a full-width grey background on hover, not a link's underline; text sits 16px from the panel's edge and the dividers are inset the same. The captures showed none of this (they're static).
- **A misspelt token name fails silently.** `var(--site-menu-background-hover)` didn't exist (the token is `site-menu.item.background-hover`), so the hover did nothing, and `check:tokens` passed: it checks that CSS uses no primitives or raw values, not that every variable exists. Idea for later: make it fail on any `var(--…)` that isn't defined in `src/tokens.css` (except a component's own custom properties).
- **Layout primitives** (glossary): small components that only arrange other things (PageContainer, Stack, Grid, Section). They take named spacing steps instead of numbers, so a screen can't drift off the 4px grid by writing its own CSS.
- **A reference can hide a value Figma can't hold.** `layout.gap.section` looks like a plain reference, but it points at a `clamp()` value. The Figma export first made it a variable aliasing nothing; it now follows the reference before deciding.
- **`font:` shorthand can't take `inherit` as the family.** The whole declaration is dropped, silently. Story headings write the font properties out one by one.
- **Skip link** (glossary): the first link on a page, hidden until keyboard focus reaches it. It jumps past the header to the main content, so keyboard and screen-reader users don't tab through every header link on every page.
- **A story's viewport also applies in the test runner.** The header's Phone story sets the phone viewport, and its test sees the Menu button, not the desktop links. A deliberately strict version proved it, so the test doesn't silently skip.
- **Route story links through RouterProvider whenever a test presses one.** Pressing the skip link (a real `#main` link) unloaded the test page and closed the test browser's connection: "Browser connection was closed".
- **The browser pane's screenshot can make a full-width page look cut short.** At an emulated 1440px it scales the page down, so the header's dark blue line appeared to stop part-way. Measure (`scrollWidth`, element widths) before concluding there's an overflow: it was 1440 of 1440.
- **In Figma a frame's outline draws on top of its children.** In CSS, Tabs' dark blue underline covers the list's grey line; drawn as the list's own outline in Figma, the grey would cover half the dark blue. The line is a separate layer placed behind the tabs (`behind: true` in the spec).
- **A turned layer's position starts from another corner.** Figma's transform gives the top-left of the layer *before* turning, so the open Disclosure's chevron (turned 180°) measured -8px from the edge instead of 8. Parity now measures the bounding box, which ignores turning.
- **An outline can grow a thin frame and drop its size's variable.** The 1px Tabs line came out 2px tall with no binding, because its outline counted towards its size. The generator now re-binds a fixed size after the outline goes on.
- **`String.replace` treats `$'` in the replacement as "the text after the match".** The Figma renderer pasted each spec into the engine with `.replace(marker, text)`; the Locale dialog's currency labels (`'USD $'`) made it paste the rest of the engine in again, so a small dialog's script came out at 87,000 characters. Passing a function (`.replace(marker, () => text)`) pastes the text as it is.
- **Hiding a layer nested in an instance isn't reliable for layout.** The Locale dialog's Tabs instance kept its 40px panel after its placeholder text was hidden. A component property that hides the whole part (Tabs' "Show panel") works, and keeps the override visible to designers.
- **Text in a Figma component wraps only if it fills its parent.** Choice card labels were auto-width, so "Australian Dollar" ran past the card instead of wrapping as it does in the browser; the dialog came out 8px shorter than the code until the text was set to fill the card.
- **Component catalogue** (glossary): `docs/catalog.json` and `docs/CATALOG.md`, generated by `npm run catalog`. One list of every component with its import path, props (types, defaults, the values each choice takes), when to use it, its Storybook stories and its Figma set, plus the types props take and the fixture data screens can use. Claude Code reads it before building a screen instead of reading every folder; CI fails if it's out of date.
- **Ask the compiler, not a regex, for props.** Button's props come in two shapes (a button, or a link with `href`). Reading the TypeScript gives every prop, which shape it belongs to, its default and its comment; and following a named type (`ButtonSize`) to where it's written keeps its values in the written order (sm, md, lg), which the compiler alone doesn't.
- **Screen** (glossary): a page built from the system in `src/screens/<Name>/`, with a story under "Screens/". It holds the state a real page would (the open dialog, the current locale) but no styling of its own; the boundary check enforces it.
- **Gap log** (glossary): `docs/screens/<name>-gaps.md`, one per screen: every point where the system had no answer, what the screen did meanwhile and what would fix it. The logs decide what the system builds next.
- **The pilot found what every page needs first.** The page shell, the smallest possible screen, already hit four gaps: no Heading, no Text, no main landmark component, no space between the header and the content. Better found on a three-line page than on all three 6c screens at once.
- **Heading level vs size** (glossary): the level (h1–h6) is the page's outline, which screen-reader users navigate by; the size is only the look. Keeping them apart lets a section's h2 look small without breaking the outline.
- **Faux bold** (glossary): when a page asks for a weight the font doesn't have loaded (700 here; only 400 and 600 are), the browser thickens the 400 itself, which looks smudged. `<strong>` asks for "bolder" by default, so Text sets it to the loaded 600.
- **Band** (glossary): a layout primitive, a strip across the whole window, white or light grey, with an optional line under it. The gallery's title band, filter bar and grey results bar are Bands, each holding a PageContainer so the content keeps the page's width.
- **Gallery view and map view** (glossary): AcmeCo's two ways of showing search results: cards two by two with no map, or the map beside a list. A link switches between them, since each has its own address.
- **ToggleButtonGroup** (glossary): a few icon buttons where one is chosen (the map's placement). React Aria exposes it as a radio group: one Tab stop, arrow keys move between the buttons, Space chooses, so looking at an option doesn't change the layout.
- **Chromatic snapshots the end of a story's test.** A story whose test switches the view (Gallery → Map) would be snapshotted showing the map. Tests that change what the story is about go in their own story with `chromatic: { disableSnapshot: true }`.
- **Redrawing a component's layers wipes what its instances override on them.** Refreshing the Figma Icons page replaced each icon's shapes, and every icon instance in the library lost its colour and stroke (all icons turned ink at the wrong weight). Parity caught it on the compact Select. Repaired from the specs; the Icons script now leaves existing icons untouched and draws only new ones.
- **A swapped icon doesn't inherit its slot's overrides.** Icons swapped into a nested Icon button (a dialog's Close, a photo's arrows) kept their own appearance, so they needed the repair too: each copies the paint and stroke of its main component's icon.
- **Parity data can change without the Figma file changing.** Re-reading the code's States matrices after decision 42 showed the phone header and phone cards moved on in code; Figma's phone variants still show the old layout until they're rebuilt.
- **A set rebuilt in the library is a new set to every other file.** The generator removes and recreates a component set, which gives it a new key: instances of it in another file (a proposals page) stay linked to the old one. Publish after a rebuild, re-read `figma/library-keys.json`, and regenerate the screens. Editing a main component in place (the card photo's aspect lock) keeps the key.
- **Screen markers** (glossary): `data-ds` attributes each component puts on its rendered root (src/components/ds.ts): the Figma set, the variant and the text it shows. The screen generator reads them; the page doesn't change.
- **Figma's Back action is "the placement last used".** A prototype can't remember state, but a hotspot whose action is Back returns to the frame the visitor came from, which is exactly rule A of the map and gallery model.
- **Resizing a layer inside an instance does nothing.** Matching a card's photo to a narrower card had to be done in the library (lock the photo's aspect ratio in the main component), not on the instance.
- **Figma can't split a resized width by a ratio.** Auto layout grows children equally or not at all, so a fact's 45 / 55 label and value only exist at the width they were drawn. A Fact list instance doesn't shrink into a narrower card; the Card's Figma set draws its own facts at its own width instead.
- **A selector inside a matrix cell can match through the matrix's own table.** `querySelector('tbody tr:first-child')` run on a States-matrix cell matched the Table's header row: the matrix's `tbody` is an ancestor, and the header `tr` is a first child inside it. Anchor parity selectors to the component (`[role=grid] > tbody > tr:first-child`).
- **An empty auto-layout frame keeps Figma's default 100px height.** The Table's hidden-label Details heading had no children, so the header row grew to 100px; cells that fill the row's height (`fillHeight`) fix it.
- **React Aria features can exist before they're public.** Table 1.22 handles child rows (`expandedKeys`, `treeColumn`) at runtime, but they're missing from its types and docs; a design system shouldn't build on them until they are.
- **A frame placed by coordinates breaks if auto layout is switched on.** Shift+A on a generated screen lines every layer up in a row (the left proposal frame went blank: its layers ran off to the right). The screen generator now sets `layoutMode = 'NONE'` when it refills a frame.
- **Figma's fill isn't CSS's 1fr when a child has padding.** Two fill columns came out 318 and 350px because the text column's 32px of padding counted on top of its share. A Figma grid with FLEX (fr) columns splits exactly, and keeps splitting when the instance is resized (`gridColumns` in the generator).
- **A library set nobody has published can't be used in another file.** New sets (Breadcrumbs, Card, Fact list, Table) are invisible to the proposals file until the owner presses Publish in the library; the screen generator reports them as "not published" and leaves them out.
- **Add a variant property to every variant in one go.** Renaming one variant of a set to add a property ("Width=Phone, Page=Default") leaves the set inconsistent, and Figma then refuses to read any variant's properties until all are renamed. Rename them all first, from their names, then read.

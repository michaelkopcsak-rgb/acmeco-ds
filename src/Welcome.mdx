# acmeco-ds: start here

A working model of an AI-ready design system. Tokens, about 40 accessible components, this Storybook and a Figma library are all generated from one repository, with the governance that lets an AI coding agent build with the system without drifting from it. Listings, people and photos are made up.

## The idea

A design system structured as machine-readable infrastructure, not just a component library:

- **Tokens carry semantic meaning:** each says what it's for and where its value came from, not only what it is.
- **Components encode reasoning:** each states when to use it, when not to, and why.
- **AI agents consume it directly,** alongside people: a generated catalogue of every component and a screen-building guide let an agent assemble pages from the system alone, and log what the system can't yet do.
- **Contributing means adding to the grammar, not just the vocabulary:** a new component comes with the rules for combining it.

## How it stays consistent

Every change goes through a pull request. CI runs lint and type checks, a token check (every token labelled, no raw values in components), a contrast check of every variant and state, boundary checks (product components and screens use only the system), a catalogue drift check, and interaction tests with axe on every story. The Figma library is generated from the same tokens and checked against the rendered code. The rules for what an agent may do alone, and what needs a designer's approval, are in `docs/GOVERNANCE.md`.
